# 아미나요양병원 시설팀 업무도구 (Facility Team Portal)

아미나요양병원 업무포털 중 **시설팀** 전용 모듈입니다. 보일러·소방시설·정수기 점검, 태블릿 대여 관리, 실시간 시설요청(라인 봇 연동) 현황판, 계정/권한 관리 기능을 하나의 정적 HTML 페이지로 제공합니다. 별도 서버 없이 브라우저에서 바로 열어 사용할 수 있으며, 데이터는 Firebase(Firestore + Realtime Database + Authentication)에 저장됩니다.

> ⚠️ 본 코드에는 `policy-library`, `incident-report-*`, `qps-*`, `psi-*`, `org-*` 등 이 문서에 담긴 스니펫에는 정의되어 있지 않은 다수의 `showPage` 분기(및 대응 `init...()` 함수)가 참조되어 있습니다. 즉 이 파일은 병원 업무포털 전체 중 **시설팀 화면과 공용 스크립트가 포함된 일부**이며, 나머지 팀(원무팀·간호팀·진료원장·영양팀·재활치료팀·상담팀 등) 화면은 별도 파일/섹션에 있는 것으로 보입니다. 그대로 배포하면 해당 미정의 함수를 호출하는 메뉴에서 `ReferenceError`가 발생할 수 있으니, 실제 배포 전 누락된 함수/페이지가 없는지 확인이 필요합니다.

## 주요 기능

### 1. 로그인 / 권한 게이트
- Firebase Authentication 기반 아이디·비밀번호 로그인 (아이디를 `아이디@amina-portal.local` 형식 이메일로 변환해 로그인)
- 계정이 하나도 없는 최초 배포 상태를 자동 감지해 "관리자 계정 최초 설정" 화면을 표시 (`system/config` 문서 존재 여부로 판단)
- 환자/보호자가 QR로 진입하는 반납 사진 업로드 화면(`tablet_photo`, `return_photo`, `accessory_return_photo`)은 로그인 없이 바로 접근 가능

### 2. 🔥 보일러 점검
- 병실(호실)별 주간 점검표 작성/조회 (누수·실리콘·소음/진동 상태, 현장 사진, 수리 내용/금액/여부)
- 점검 이력 관리대장: 호실별 이상 발생 이력·횟수·누적 수리금액, 전월/당월 이상 발생 통계
- 호실별 QR 라벨 생성/인쇄 → 스캔 시 해당 호실 현장 점검 화면으로 바로 진입
- 로컬 저장(localStorage) → Firebase 이전, 구버전 Firestore 스키마(`boiler_checks`) → 신버전(`boiler_room_checks`) 이전 유틸리티 포함

### 3. 🧯 소방시설 점검 (소화기 / 옥내소화전)
- 층별·위치별 소화기(설치장소/거리/적응성/위치표지/소화약제/레버/본체/호스/지시압력계/안전핀) 및 옥내소화전(위치표시등/가압송수장치/장애물/수원·밸브/배관/호스·관창/동파위험) 점검표
- 층 필터 버튼(B4~7F)으로 화면만 필터링(값은 유지되어 층 전환 시 입력값이 사라지지 않도록 설계)
- 층별 연간 관리대장: 소화기는 O/X 월별 종합 판정, 소화전은 점검 항목별 월별 O/X — 셀 클릭 시 해당 점검일 점검표로 이동
- 위치별 QR 라벨 생성/인쇄

### 4. 💧 정수기 / 이온수기 필터 관리
- 관리번호(기기)별 마스터 데이터(설치위치/모델/제품/필터단계별 명칭·교체주기) 하드코딩 관리 (`WATER_UNITS`)
- 통합 관리 현황판: 최근 점검일, 차기 예정일, D-Day, 상태(정상/점검예정/교체요망/미교체/업체관리) 자동 산출
- 필터 교체 입력: 같은 모델 기기 일괄 선택, 교체 필요 필터 자동 체크
- 필터별 세부 교체 계획표, 기기별 교체 이력, 월별 입력 이력 조회
- 기존 스프레드시트 최근 교체기록 1회성 시드 데이터 업로드 기능

### 5. 📱 태블릿 / 부속품 대여 관리
- 태블릿(01~80번) 대여/회수 처리 — QR 스캔(직원용) 또는 수동 선택으로 진입, 현재 대여 상태에 따라 제공/회수 화면 자동 분기
- 부속품(스탠드/이어폰/충전기) 단독 대여 등록, 병실번호+성함으로 대여 건 조회 후 반납사진 제출(환자용)/회수 처리(직원용) — 재사용 가능한 QR 1장으로 운영
- 이용약관 동의 + 캔버스 서명 수집 (서명 불가 시 "사전 설명 완료" 체크로 대체)
- 반납 시 환자가 남긴 사진을 직원이 확인할 수 있도록 이력 화면에 노출, 분실/파손 배상 금액 안내(`DAMAGE_FEES`)
- 태블릿(직원용/환자용 반납사진 2종) 및 부속품 등록·반납·회수 QR 라벨 일괄 인쇄

### 6. 🔔 실시간 시설요청 현황 (라인 봇 연동)
- Realtime Database `facility_requests` 경로를 실시간 구독하여 라인 단톡방에 올라온 수리요청을 표시
- 키워드 기반으로 시설요청이 아닌 메시지(이송 안내, 테스트 메시지, 자모 깨짐 등) 자동 제외
- 답장 내용 키워드로 "진행중" vs "처리완료" 자동 판정 (완료 의미가 아닌 답장은 진행중으로 유지)
- 고장/불편 표현 기반 우선순위 자동 산정(우선/일반/후순위) 후 정렬
- 별도 팝업창으로 띄우는 미니 현황판(`?view=mini`) 지원 — 화면 구석에 상시 띄워두는 용도

### 7. ⚙️ 관리자 패널
- 신규 계정 생성(보조 Firebase 앱 인스턴스를 사용해 관리자 본인 세션 유지), 팀 접근 권한/관리자 권한 부여
- 계정별 "불러올 수 있는 서명" 접근 권한 관리(다른 직원 서명 대리 사용 목적으로 추정)

### 8. 공통 유틸리티
- 이미지 캔버스 압축(최대 800px, JPEG 0.7) 후 Firestore에 base64로 저장
- 이미지 확대 모달, 인쇄 시 가로/세로 방향 강제(`@page`), 인쇄 전용 스타일(`.no-print`)
- Firestore 문서 ID 안전 변환(`toDocIdSafe`) — 특수문자·공백 치환

## 빠른 시작

1. 이 HTML 파일을 정적 웹 호스팅(Firebase Hosting 권장, 또는 사내 웹서버)에 업로드합니다.
2. Firebase 콘솔에서 Authentication(이메일/비밀번호 로그인 방식), Firestore, Realtime Database를 활성화합니다.
3. 브라우저로 접속하면 계정이 하나도 없으므로 "최초 관리자 설정" 화면이 나타납니다. 관리자 아이디/이름/비밀번호를 입력해 계정을 생성합니다.
4. 로그인 후 "⚙️ 관리자 → 👤 계정 관리"에서 직원 계정을 추가로 생성합니다.

## 최초 관리자 설정

- `system/config` 문서가 없으면 최초 설정 화면이 표시되고, 설정 완료 시 `setupComplete: true`로 문서를 생성해 이후에는 이 경로로 관리자를 추가 생성할 수 없도록 잠급니다.
- 아이디 규칙: 영문/숫자 3~20자 (`/^[a-zA-Z0-9]{3,20}$/`), 비밀번호 6자 이상.

## QR 코드 흐름

모든 QR 라벨은 `현재페이지URL?t=종류&...파라미터` 형태이며, 접속 시 `initQrCheckFromUrl()`이 쿼리스트링을 해석해 로그인 후(또는 환자용 화면은 로그인 없이) 해당 단일 항목 처리 화면으로 바로 이동시킵니다.

| `t` 값 | 대상 | 로그인 필요 |
|---|---|---|
| `ext` / `hyd` | 소화기·소화전 현장 점검 | 필요 |
| `boiler` | 보일러 호실 현장 점검 | 필요 |
| `tablet` | 태블릿 제공/회수 처리(직원용) | 필요 |
| `tablet_photo`, `return_photo` | 태블릿/부속품 반납 사진 제출(환자용) | 불필요 |
| `accessory_register` | 부속품 단독 대여 등록 바로가기(직원용) | 필요 |
| `accessory_return_photo` | 부속품 반납 사진 제출(환자용, 병실+성함 조회) | 불필요 |
| `accessory_return_process` | 부속품 회수 처리(직원용, 병실+성함 조회) | 필요 |
| `temphumid` | 온습도 점검 입력(코드 일부만 포함, 전체 구현은 별도 모듈 추정) | 필요 |

## 계정 및 권한

- `allowedTeams`: 계정이 볼 수 있는 팀(현재 파일에는 `시설팀`만 정의됨 — 전체 포털에서는 팀별로 확장되는 구조로 보임)
- `isAdmin`: 체크 시 모든 팀 권한 자동 부여 + "⚙️ 관리자" 메뉴 노출
- `signatureAccess`: 해당 계정이 자신 외에 불러올 수 있는 다른 직원의 서명 UID 목록

## 보안 및 운영 주의사항

- **Firestore/RTDB 보안 규칙 필수 확인**: 이 파일에 포함된 Firebase `apiKey`는 클라이언트 공개 키로 그 자체는 비밀 정보가 아니지만, 실제 접근 제어는 Firebase 콘솔의 **보안 규칙(Security Rules)**이 담당합니다. 규칙이 열려 있으면 누구나 환자 정보·사진·계정 데이터를 읽고 쓸 수 있으므로, 로그인 사용자만 읽기/쓰기 가능하도록, 그리고 `portal_users`·`tablet_loans` 등 민감 컬렉션은 역할 기반으로 제한되어 있는지 반드시 점검하세요.
- **개인정보 포함**: 환자명, 병실번호, 서명 이미지, 반납 사진(base64)이 Firestore 문서에 그대로 저장됩니다. 접근 권한·보관 기간 정책을 별도로 수립하는 것을 권장합니다.
- **환자용 QR 화면은 인증이 없습니다.** URL의 `t=` 파라미터만으로 접근 가능한 구조이므로, 링크가 외부에 노출되지 않도록 QR 라벨 관리(출력물 회수, 재사용 QR 분실 등)에 유의해야 합니다.
- 관리자 계정 생성 시 보조 Firebase 앱 인스턴스(`Secondary`)를 사용하지만, 생성된 신규 계정의 임시 로그인 세션은 이후 `signOut()` 처리되므로 정상 동작 시 문제는 없습니다. 다만 네트워크 중단 등으로 `signOut()`이 실패하면 잔여 세션이 남을 수 있어 예외 처리 보강을 고려하세요.
- 배상 금액(`DAMAGE_FEES`)은 코드 내 주석에도 명시되어 있듯 **예시 금액**이므로 실제 정책 확정 전 문구 노출에 주의하세요.
